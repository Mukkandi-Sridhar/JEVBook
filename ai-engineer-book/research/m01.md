# Research notes: Module 1, Python for AI engineers

## Retries and back-off
- Exponential back-off with jitter: Marc Brooker, "Exponential Backoff and Jitter", AWS Architecture Blog.
  Jitter spreads retries so many clients do not retry at the same moment; plain exponential back-off without jitter
  does the most work and takes the longest in their simulation.
  https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/
- AWS Well-Architected REL05-BP03: use back-off with jitter and limit the number of retries.
  https://docs.aws.amazon.com/en_us/wellarchitected/2022-03-31/framework/rel_mitigate_interaction_failure_limit_retries.html

## Which model-API errors to retry
- Retryable: 429 (rate limit; honour the retry-after header when present), 500, 529 (overloaded), connection
  errors and timeouts. Not retryable: 400, 401, 403, 404 (fix the request or the key).
- The official SDKs already retry transient errors a small number of times by default (Anthropic: 2), so a retry
  loop written on top multiplies attempts. [[VERIFY against provider docs before print]]
  https://www.developersdigest.tech/blog/ai-api-rate-limit-retry-guide-2026
  https://open-exam-prep.com/study-guides/anthropic-ccdv-f/ch4-api-resilience-backend-state/api-resilience-error-handling

## Tool schemas from type hints and docstrings
- Agent SDKs build a tool's JSON schema from the function name, type hints and docstring, and validate the
  arguments with a generated Pydantic model (OpenAI Agents SDK `@function_tool`; AG2, Agno and others similar).
  So in AI work, the docstring and type hints are read by the model.
  https://instagit.com/openai/openai-agents-python/how-to-create-use-functiontool-custom-python-functions
  https://docs.ag2.ai/docs/user-guide/tools/tools/

## Our own worked numbers (assumed example values)
- 4,000 messages × 3 s each, one at a time = 12,000 s = 3 h 20 min.
- 20 at a time: 4,000 / 20 × 3 s = 600 s = 10 min. That is 400 calls a minute; a 100-a-minute limit sets a floor
  of 40 minutes whatever the code does.
- Five attempts, four waits of at most 1, 2, 4, 8 s: worst-case wait 15 s before giving up.
- SDK retries 2 (3 attempts) × our loop 5 attempts = 15 attempts for one message.
